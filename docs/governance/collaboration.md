# 协作、文档与验证

从[根协作约定](../../AGENTS.md)定位本轮任务，再经[当前状态](../status/current.md)和[专题地图](../topics/README.md)确定范围和事实来源。文档、实现或自动化检查口径出现差异时，核对已确认的决定、实际行为和证据，找出需要更新的一方。

## 从讨论进入实施

- 说明、诊断和评审交付可定位的发现，写清预期与实际行为、影响范围和证据。规划交付范围、取舍、依赖与验收条件。探针先定义问题、输入、隔离环境、判据和结束条件，实测发现可供正式方案引用。
- 用户要求实施时，先定位子专题和拟交付批次，核对现有调用方和正常入口。涉及隐私承诺、破坏性数据库变更、公开接口兼容性或真实系统接入时，先说明影响，按当前授权覆盖的范围推进。
- 已授权的文档、实现和配置变更可沿现有任务直接完成。若新发现涉及授权之外的方案变更、外部动作或持久数据修改，只就新增部分确认范围。

## 工作区与运行操作

- 有 Git 时先看 `git status --short --branch`，按需查看暂存和未暂存差异。发现用户已有改动或并行改动时按路径核对归属。同一文件发生重叠时尽可能局部编辑，需要覆盖或回滚既有内容时先确认。无 Git 时按文件核对所需变更。
- 用相应的开发命令和隔离环境验证当前变更。依赖恢复沿仓库现有锁定版本，新增或升级依赖时说明用途、影响及锁文件变化。需要启动服务时核对环境、端口、数据目录与依赖，记录启动方式并清理本轮创建的临时进程和数据。明确交付持续运行的环境时，交接进程用途与停止方式。
- 清理前核对解析后的具体路径和进程归属，临时资源只清理本次创建且归属明确的部分。必要检查因权限、网络或工具受阻时记录实际错误，并在已有任务授权内解决环境问题。
- 操作外部系统前核对已授权的目标仓库、实例或账号，以及预期写入、关键副作用和可用的恢复方式。构建、提交、推送、开 PR、合并和发布各有不同影响，按任务所要求的动作执行。
- 验证优先使用合成账号、消息和隔离数据目录。需要真实环境时，按授权处理数据，分享前检查日志、截图、导出和命令输出中的敏感内容。

## 规划与进度的归属

| 层级 | 维护内容 | 入口 |
| --- | --- | --- |
| 整体规划 | 产品、范围、跨专题优先级、阶段和整体退出条件 | [项目整体规划](../planning/project-plan.md) |
| 大专题 | 一个持续能力的范围、依赖、下辖子专题和目标版本出口 | [能力专题地图](../topics/README.md) |
| 子专题 | 功能合同、依赖、阶段、执行状态、验收标准和证据链接 | 主题页的稳定锚点，必要时链接单独设计或实施表 |

每个子专题只有一个主归属，多个专题协作时引用彼此接口和验收。阶段是交付顺序，专题是能力归属。任务和切片放在子专题或其指定的实施表里。任务达到需联合评审的复杂度时，先补用户场景、数据和接口边界、正常路径、失败与恢复方式、验收及退出条件。

方案状态用草案、已确认、已替代。执行状态用待开始、进行中、待验收、已完成。需要等待时记录原因、恢复条件和负责人角色。完成判定绑定具体切片及证据。一次实现写入源码以后可进入待验收，只有规定范围验证通过才标已完成。

[当前状态](../status/current.md)维护现阶段顺位、阻塞和接续入口。详细结果记录在 `docs/records/`，已有历史证据在原路径继续引用。ADR 记录长期决定及其后果。接口文档说明指定版本的行为。更新切片时同步核对总规划、索引链接和当前状态，按影响修改对应入口。

## 验证与留痕

- 文档和治理运行 `python3 scripts/check-repo.py`，核对变更差异。普通开发选择与改动相称的格式、静态检查、构建或定向测试。存在 Git 基线时复核 `git diff --check`、暂存差异和未跟踪文件。
- 产品实现按专题验证正常、拒绝和恢复路径。涉及用户可见交互时，以对应运行环境里的实际路径验证交互。服务端、Web、OIDC 模拟、真实 Radish、容器、自部署 HTTPS 和真机分别记录环境和结果。
- 测试应覆盖可观察的行为、边界和失败路径。检查规则或验收口径有意变更时，同步更新正式文档和自动检查，并记录新的通过条件。
- 失败时记录触发条件和表现，区分产品缺陷、验证手段故障和环境阻塞。复验使用明确判据，保留适用的失败证据。交接写清实际完成的范围、版本或源码身份、执行的检查与结果、待复验项，以及与任务有关的工作区状态和外部动作。
- 稳定化 PR 提供本批次验收证据以及回流安排。发布或部署单独核对目标产物、配置、备份、兼容性与回滚。CI 组成以[仓库治理](repository.md)为准。
