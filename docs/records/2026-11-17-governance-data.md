# OPS-02-03 受控导出、到期清理与恢复验收

2026-11-17，在 `dev` 基线 `6c15ade` 上，以工作区构建的 Go 候选验证 SQLite v11、实例资料导出、到期清理及快照恢复。环境为 macOS arm64、Go 1.26.3 和 Python 3.9.6。两个独立 Go 实例各用一个临时 SQLite 文件，由各自的回环 HTTPS 反代提供入口。测试客户端信任临时测试证书并校验其回环地址，所有账号、邀请码、Bot、群聊和消息均为合成数据。本次联合验收覆盖实际 HTTPS API 与维护 CLI；浏览器举报入口沿用单项验收证据。[治理实施条目](../topics/deployment.md#ops-02-03) · [举报入口验收](2026-11-17-group-message-reports.md)

| 检查 | 实际结果 |
| --- | --- |
| 双实例准入 | 两侧使用相同的合成用户名和账号 ID。跨实例邀请码、Cookie 和 Bot 凭据被拒绝。A 轮换邀请码后，旧码被拒、新码可注册、已有会话仍有效。恢复后关闭 A 的注册，已有成员仍可登录。 |
| 举报与撤权 | 在 A 用群成员会话提交举报，维护 CLI 可审阅所报消息并结案。普通成员和群主无数据维护 HTTP 入口。停用结案使被举报作者的旧 Cookie 和 Bot 凭据失效，其他成员仍可读取历史和发送消息。 |
| 本人导出 | 在 A、B 分别生成 `0600` JSON 并逐字段核对。账号仅含 ID、用户名、显示名和状态，举报仅含编号、原因、创建时间、状态和适用的结案时间。排除了另一举报人、到期举报、群和消息引用、正文及凭据。核实用户名与目标账号不匹配时无输出。单项测试也验证停用账号可经核实导出、已有文件拒绝覆盖、导出审计失败时无文件。 |
| 到期清理 | 在 A 的合成记录上设置早于期限的时间。首次执行删除 2 条到期结案举报和 1 条到期审计，返回数量与 `data.prune` 审计一致；再次执行返回 0 和 0。近期结案、长期待处理举报、近期审计及原消息均可核对。B 的举报和维护审计保持独立，Bot 能继续读取新命令并回复。单项测试注入审计写入失败，验证两类删除同时回滚。 |
| 快照恢复 | 将 A 在清理后的 v11 快照恢复到隔离新库，维护审计和导出、清理记录一致。另将停用和部分结案之前的 A 快照恢复到新库，核对旧凭据被清除、旧账号状态和案件状态按快照还原、已有结案时间保持原值。复开前用维护记录补做停用与结案。一个恢复为待处理的案件按原时间结案后立即满足 30 天期限。再次清理删除同样的 2 条举报和 1 条审计。复开后，旧会话和被停用账号无法登录，其他成员重新登录后可读原历史，导出内容与恢复前一致，B 的会话、审计及聊天记录保持独立。 |
| 迁移 | 自动化定向测试验证 v10 至 v11 保留举报状态、结案时间、审计编号和操作时间，注入迁移失败后保留 v10 原库。补做结案测试验证非法原时间被拒绝、同结果同时间可重跑、到期后从正常审阅和活动库移除。 |

复跑时从仓库根目录执行 `go build -mod=readonly -o "$acceptance_dir/radishchat" ./cmd/radishchat`，将候选输出到本次验收的临时目录。按回环 HTTPS 双实例配置或等效反代启动两个候选。使用独立合成数据依次执行邀请码轮换、举报与审阅、停服备份、结案停用、字段校验及清理，再按操作记录将快照恢复到新路径，补做结案后清理并复开。时间边界通过回写隔离库内合成记录的 `created_at`、`closed_at` 和 `occurred_at` 复现。到期判断使用实际运行时间。[双实例配置](../../deploy/README.md#双实例验收) · [维护与恢复步骤](../../deploy/README.md#sqlite-backup-restore)

Go 构建、定向治理与迁移测试、全量 `go test -mod=readonly -count=1 -race ./...`、`go vet -mod=readonly ./...` 和仓库差异检查通过。回环服务已停止，验收证书、SQLite 文件、快照、导出文件及临时构建目录已清理。
