# BOT-02-02 Bot 回复与群展示本机验收

2026-11-15，在本地 `dev` 的 `8dd3503` 上实现显式回复权限、Bot 消息写入和 Web 群内操作。真人作者保持整数 ID，Bot 作者使用 `kind: "bot"` 和字符串 ID。SQLite v7 将两类作者写入同一消息表，消息共用顺序及成员历史下限。[实施表](../topics/bots.md#bot-02-02) · [回复 API](../api/v1.md#bot-command-replies)

本机为 macOS 27.0.1 arm64、Go 1.26.3、Docker 29.8.2、Compose 5.5.0、Playwright CLI 0.1.24。Linux ARM64 候选 `radishchat:p2-bot-reply-8dd3503` 由该提交和本批运行时代码构建，镜像 ID 为 `sha256:1108eba7d5c905dbcbde248b1343db5fedf93e2058f1e776661c883a89c8e502`。验收实例使用回环地址、本地 HTTPS 和合成账号。浏览器用合成凭据直接调用 Bot 接口，常驻示例 Bot 的验证归入 [BOT-02-03](../topics/bots.md#bot-02-03)。

| 检查 | 实际结果 |
| --- | --- |
| 安装、命令与群展示 | 群主在 Web 显式选择接收和回复权限，独立 Bot 所有者批准跨账号安装。待审批时没有命令按钮。390 像素宽的普通成员界面发送 `ping` 后确认入队，轮询只得到这一条显式命令。提交 `**pong**` 后，成员通过现有同步通道收到带展示名和 `Bot` 标识的粗体回复。桌面端重载可读到同一条记录，原真人消息仍使用数字作者 ID。另一 HTTPS 实例拒绝该凭据。 |
| 回复写入和授权 | 测试丢弃首次 `201` 的响应正文，同文重试返回 `200` 和相同消息，异文返回 `409`，历史只增加一条。无 Origin 的 Bearer 写入通过，真人 Cookie 单独调用回复返回 `401`，真人写接口保留同源校验。仅接收权限、其他安装事件、重复安装请求头和已撤销授权返回 `404`，旧凭据返回 `401`，过期事件返回 `410`。Web 移除安装后新回复被拒绝，已发送回复仍可读。 |
| 历史与恢复 | 前向补拉和向前分页按消息 ID 返回 Bot 或真人消息。后加入的成员读不到加入前的回复，Bot 所有者身份本身无法读取群历史。备份恢复后原成员重新登录，读到相同的真人和 Bot 记录，旧凭据失效，待交付事件和安装为空。 |
| SQLite 迁移 | 在 v6→v7 重建消息索引时注入失败，确认旧消息表、版本与权限完整回滚。排除故障后迁移保留原消息字段、成员历史下限、接收权限与事件序号，旧安装未获得回复权限。固定 v1 样本经 CLI 备份、恢复、启动升级到 v7 后正常重启。v7 的备份和还原保留五条原始消息及成员历史下限，SQLite 完整性和外键检查通过，原样本摘要一致。 |
| 工程检查 | 定向回复与迁移测试、`go test -mod=readonly -count=1 -race ./...`、`go vet -mod=readonly ./...`、Go 构建、Docker 构建中的 Web 类型检查与生产构建、`python3 scripts/check-repo.py` 和 `git diff --check` 均通过。 |

本地候选镜像保留供复核。浏览器会话、临时容器、网络、数据卷与验证数据已清理。
