# BOT-02-01 命令事件入队与拉取本机验收

2026-11-15，在本地 `dev` 的 `7fc7a19` 上接续 `BOT-02` 设计，实现 SQLite v6、显式接收权限、`ping` 入队和短轮询。Bot 回复写入、作者模型和 Web 命令入口由 `BOT-02-02` 接续。[实施表](../topics/bots.md#bot-02-01) · [命令事件 API](../api/v1.md#bot-command-events)

本机环境为 macOS 27.0.1 arm64 和 Go 1.26.3。库内测试使用隔离缓存、临时 SQLite 和合成账号。命令行复验使用本机构建的 `radishchat` 二进制、回环端口与固定预览 v1 样本的副本。

| 检查 | 实际结果 |
| --- | --- |
| 权限与隐私 | 原安装保持 `installation:read`。群主移除旧安装并显式授予 `commands:receive` 后，仍须由 Bot 所有者批准跨账号安装。待审批、无接收许可、跨群和旧安装 ID 请求被拒绝。普通聊天文本 `ping` 不入队，事件仅返回约定字段和显式命令。群成员移除后拒绝新命令，重新加入后旧成员资格的去重记录不会被复用。 |
| 提交、分页与续读 | 同一请求 ID 和成员资格重试返回原事件。改用其他命令返回 409。注入去重记录写入失败，事件、序号和去重记录全部回滚。27 条命令跨默认页按序返回，重读结果一致，空页保持游标。回环二进制重启后可用原游标续读，原命令重试保持同一事件 ID。 |
| 保留窗口及限流 | 容量达到 1,000 条时，新提交清理最早事件但保留其有效去重摘要。容量与 7 天到期缺口均返回 410 与恢复边界。测试直接执行定期清理所用事务，验证过期事件、摘要和清理边界一致。错用安装游标或超出已提交位置返回 400。第 121 次拉取及第 61 条新命令返回 429 与 `Retry-After: 60`，其他安装与其他发起账号仍按各自配额接入。 |
| 迁移与恢复 | v5→v6 在建索引时注入失败，验证回滚保留原安装。重新迁移后凭据和基础许可有效，旧安装仍无法拉取命令。固定 v1 样本正常升至 v6，旧群历史下限和五条原始消息保持。备用副本与恢复库均清除安装、凭据、事件和去重记录，保留普通消息。恢复后重新签发凭据和授予安装得到空事件队列，旧游标被拒绝。原样本摘要复核一致。 |
| 工程检查 | 定向 API、迁移与备份用例，`go test -mod=readonly -count=1 -race ./...`、`go vet -mod=readonly ./...`、Go 构建、`python3 scripts/check-repo.py` 和 `git diff --check` 均通过。 |
