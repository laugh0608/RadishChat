# BOT-01-02 群安装与撤权本机验收

2026-11-15，在本地 `dev` 的 `70f376c` 之上实现并验收群安装 API、撤权和 SQLite v5。跨账号安装由群主发起、Bot 所有者批准，同一所有者可直接安装。首批群权限为 `installation:read`。Web 管理入口与双实例浏览器验收由 `BOT-01-03` 接续。[实施表](../topics/bots.md#bot-01-02) · [API](../api/v1.md#bot-installations)

本机环境为 macOS 27.0.1 arm64、Go 1.26.3。Go 使用隔离的依赖及构建缓存。集成测试使用临时数据库、回环实例及合成账号。命令行复验使用本机构建的二进制和固定预览 v1 样本的副本。

| 检查 | 实际结果 |
| --- | --- |
| 安装与可见性 | 群主预览并明确提交许可。`pending` 状态对普通成员和 Bot 不可用，Bot 所有者可以查看请求并审批。生效后普通成员可查 Bot 名称和权限。权限缺失、未知或重复时均拒绝安装。非成员、私聊和缺少安装授权的群按合同拒绝。 |
| 撤权与并发 | 群主和 Bot 所有者均可移除，其他群的安装保持可用。重复安装请求只保留一条记录。移除后重装使用新 ID，旧 ID 的审批、移除和带期望安装 ID 的 Bot 查询均被拒绝。用合成 SQL 变更群主验证审批前复核申请人。重复运行并发审批与移除测试，最终授权均已删除。 |
| 权限范围 | 获准的凭据仅返回 Bot ID、群 ID、安装 ID 和权限。Bot 仍无法使用真人接口读取成员或正文。凭据轮换后旧凭据在已有群安装上返回 `401`，新凭据仍按原安装授权。真人成员被移出后失去群的安装列表访问。 |
| 迁移 | v4→v5 在创建安装表后注入索引创建失败，验证回滚保留 v4，解除故障后迁移成功，既有 Bot 凭据、消息及成员历史下限保留。固定 v1 样本副本启动后升级至 v5，五条原消息保留，旧群历史继续按加入边界隐藏。完整性和外键检查通过，原样本摘要一致。 |
| 备份与恢复 | v1 至 v4 副本保留原版本。v5 正常重启保留生效及待审批安装，待审批状态继续拒绝 Bot 访问。`radishchat backup` 和 `radishchat restore` 清除两种状态的安装及 Bot 凭据，保留 Bot 定义与所有者。重新签发也无法复用旧安装，重新发起和审批后才恢复访问。副本文件为 `0600`，合成登录密码和 Bot 凭据未出现在复验日志中。 |
| 工程检查 | 定向 API、迁移与备份测试，`go test -mod=readonly -count=1 -race ./...`、`go vet -mod=readonly ./...`、Go 构建、`python3 scripts/check-repo.py` 与 `git diff --check` 均通过。 |

复验使用的临时进程和数据已清理。
