# AUTH-03-02 一次性恢复与重新开放验收

2026-11-17，在 `dev` 基线 `b89da8c` 上实现 `account issue-recovery`、`account reopen` 和 Web 密码重置。SQLite 沿用 v8。签发或重签时同步撤销目标旧会话，重置时在一个事务内消费有效码、更新密码并恢复账号。Web 凭新密码走常规登录。[实施条目](../topics/identity.md#auth-03-02) · [维护步骤](../../deploy/README.md#local-account-disable)

本机为 macOS 27.0.1 arm64、Go 1.26.3、Node.js 24.16.0。Web 使用锁文件构建后的产物，Playwright CLI 0.1.22 驱动 Chromium。服务与测试实例仅使用回环 HTTP、独立 SQLite 数据库和合成账号，原有合成 OIDC 验收随全量 Go 测试复跑。

| 检查 | 实际结果 |
| --- | --- |
| 签发、重签与停用 | 维护命令输出一枚 32 字节随机值编码的恢复码，库内记录摘要和 15 分钟有效期。签发后旧 Cookie 和密码不能登录，普通签发保留该账号的独立 Bot 授权。到期、重签后的旧码、错误账号和不存在的账号均返回通用 `401`。停用清除当时签发的码，`issue-recovery` 拒绝已停用账号。`reopen` 仅接受已停用账号，重新开放后仍须完成重置才能登录。 |
| 并发、回滚和限流 | 同一码并发提交分别返回 `204` 与 `401`，成功响应无新会话 Cookie。变更后的同码重试与原 Cookie 继续返回 `401`。弱密码或与原密码相同返回 `400`，码仍可使用。注入签发写入及消费失败时对应事务回滚，恢复后可重试。异源请求被拒绝，来源和规范化用户名分别达到限额时返回 `429` 和 `Retry-After`。 |
| 独立实例与快照 | 两个实例里相同用户名和用户 ID 各有独立码，跨实例码返回 `401`，其他实例仍可正常恢复。在等待恢复期间备份并恢复，副本保留状态、失效旧码，可用新码恢复。对早于停用的快照重新应用停用，旧密码无法登录，核对后 `reopen` 并设置新密码才能重新登录，原账号 ID 保留。 |
| 390 × 844 Web 主路径 | 用实际 CLI 签发，停用后拒绝普通签发，再用 `reopen` 出新码。关闭注册仍有「忘记密码？」入口。重置表单无横向溢出，旧码被拒绝，使用新码时与旧密码相同的请求被拒绝，改用新密码后返回登录页。旧密码继续失败，新密码登录后读取原群消息。 |
| 工程检查 | Go 构建、全量 `go test -mod=readonly -count=1 -race ./...`、`go vet -mod=readonly ./...`、`npm ci --no-audit --no-fund`、`npm run build`、仓库检查和差异检查均通过。 |

临时服务和浏览器会话已关闭。合成数据库、恢复码、日志和构建目录均已清理。
