# BOT-01-01 独立身份与凭据本机验收

2026-11-15，在本地 `dev` 的 `d7e5024` 之上实施并验证 `BOT-01-01`。本批交付独立 Bot 记录、所有者管理、Bearer 自检和 SQLite v4。群安装关系随 `BOT-01-02` 迁移，安装和 Web 管理的联合复验由后续任务承接。[实施表](../topics/bots.md#bot-01-01) · [接口说明](../api/v1.md#bot-identity)

本机环境为 macOS 27.0.1 arm64 和 Go 1.26.3。Go 使用隔离的依赖及构建缓存。API 测试用独立回环实例、临时数据库和合成账号。命令行复验使用本机构建的二进制、回环端口及固定样本的临时副本，测试结束后停止实例并清理本轮临时数据。

| 检查 | 实际结果 |
| --- | --- |
| 身份与所有权 | Bot 记录独立于真人账号和群成员。相同展示名可用于不同 Bot。所有者只能列出和管理自己的 Bot。其他账号、另一实例、跨源写请求、会话与 Bearer 交叉使用均按合同拒绝。 |
| 凭据与异常恢复 | SQLite 只保存凭据摘要，签发响应携带 `no-store`。注入轮换写入失败后原凭据仍可用。丢弃签发响应后重新轮换可取得可用凭据。四次并发轮换只有最后一次提交的凭据可用，撤销重复执行返回 `204`。 |
| 迁移 | 干净库及 v1、v2、v3 升至 v4。v3→v4 在创建表后故意让索引创建失败，确认事务回滚、原用户数据保留，解除故障后可重新升级。固定 v1 样本经维护命令备份、恢复并启动后升至 v4，原私聊可读，旧群历史按加入边界继续隐藏。原样本的字节摘要复核一致。 |
| 备份及恢复 | v1 至 v3 副本保留原版本。v4 库正常重启保留 Bot 凭据。`radishchat backup` 和 `radishchat restore` 清除副本凭据，保留 Bot 定义和所有者。恢复后的旧凭据返回 `401`，所有者重新登录并签发后可接入。升级库的完整性和外键检查通过，备份及恢复文件均为 `0600`。复验的进程日志未发现合成 Bot 凭据或登录密码。 |
| 工程检查 | 定向 Bot、迁移和备份测试、`go test -mod=readonly -count=1 -race ./...`、`go vet -mod=readonly ./...`、`go build -mod=readonly -trimpath ./cmd/radishchat`、`python3 scripts/check-repo.py` 和 `git diff --check` 均通过。 |
