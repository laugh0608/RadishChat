# OPS-02-02 普通群举报与结案验收

2026-11-17，在 `dev` 基线 `434dc08` 上实现 SQLite v10、普通群消息举报和维护 CLI。案件保存原消息引用，审阅原文之前记录审计。停用结案复用账号撤权和审计，同一次提交关联举报编号。[维护步骤](../../deploy/README.md#message-reports) · [举报 API](../api/v1.md#group-message-reports)

本机为 macOS arm64、Go 1.26.3、Node.js 24.16.0。原生 Go 候选仅监听回环 HTTP，使用独立 SQLite 和合成成员。Playwright CLI 0.1.22 使用本轮生产构建完成窄屏 Web 路径，维护操作使用候选二进制执行。

| 检查 | 实际结果 |
| --- | --- |
| Web 和举报授权 | 390 × 844 视口可在群消息下查看告知、选原因、提交并获得编号，页面及消息区无横向溢出。私聊无举报入口。API 对跨群、加入前消息、离群、旧成员资格和重新加入后已不可见的消息返回 `404`，失效会话返回 `401`。同原因重试返回原编号，改原因返回 `409`，超过账号限额返回 `429`。 |
| 审阅与证据 | 实际 CLI 列表只含元数据；审阅返回所报一条消息并写关联审计。注入审阅审计失败时未交付原文。模拟原消息删除并重用其 ID 后，旧举报仍返回证据不可用，可结案结束处理。应用诊断和审计查询均不含举报原文。 |
| 结案及撤权 | 注入结案审计失败后，举报仍待处理，作者会话与 Bot 授权继续可用，停用审计也回滚。重试成功后旧 Cookie、SSE 和所属 Bot 授权失效，群内其他成员仍能读取原消息和继续发送。按相同结果重跑时返回原结果，尝试改写结果时被拒绝。Bot 举报可记录转交群主，停用结案拒绝以 Bot 身份为目标。 |
| 升级、备份与留存 | v9 迁移失败保持原库和原审计，成功升至 v10 后保留已有审计编号、时间和结果。CLI 备份恢复保留案件和关联审计，清除会话。测试中到期的结案记录从 30 天查询窗口排除，数据库到期清理接续于 OPS-02-03。 |
| 工程检查 | Go 构建、定向举报与迁移测试、全量 `go test -mod=readonly -count=1 -race ./...`、`go vet -mod=readonly ./...`、`npm ci --no-audit --no-fund`、`npm run build`、仓库检查及差异检查通过。 |

隔离服务与浏览器会话已关闭，合成数据、备份、日志和构建目录已清理。
