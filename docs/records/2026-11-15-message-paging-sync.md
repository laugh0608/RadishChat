# P1 消息分页与补拉验收

2026-11-15，[MSG-02-02](../topics/messaging.md#msg-02-02) 通过单项验收。以 `8738d37` 为源码基线，叠加本轮改动。在 macOS 27.0.1 arm64 上用 Go 1.26.3、Node.js 24.16.0 构建。测试使用本机回环 HTTP、临时 SQLite 和合成账号。

| 检查 | 实际结果 |
| --- | --- |
| 游标与页尾 | Go 集成测试覆盖默认最近一页、从 `after=0` 开始、排除边界 ID、双向分页及空页。验证超过 50 条时 `more=true`、恰好 50 条时 `more=false`。通过交错写入及另一会话占用消息 ID，核对消息顺序和数量。无效或混用游标返回 `400`。 |
| 授权与实时信号 | 房间退出后 `after=0` 被拒绝。重新加入再使用旧游标，分页只返回本次加入后的消息。断开并重新打开 SSE，核对首次和后续帧的 `data: {}`，帧中无会话标识或正文。 |
| Chromium 恢复已有会话 | 最初只显示 100 条历史中的最近 50 条。断网时写入 107 条，恢复后暂缓交付补拉第一页，同时前翻更早历史并继续写入。又以浏览器账号发送一条并取得确认。释放首个响应后，补拉从 `after=100` 依次推进到 `150`、`200` 和 `213`，比对页面上从首条到第 213 条的内容和顺序，完全一致。 |
| Chromium 恢复空会话 | 浏览器确认群内暂无消息后断网，另一账号写入 108 条。恢复后首个增量游标为 `0`，跨三页完整显示全部消息。两个浏览器场景均观察到离线时关闭 SSE 和恢复后重新建立连接。 |
| 工程检查 | Go 构建、`go test -mod=readonly -count=1 -race ./...`、`go vet -mod=readonly ./...`、Web 离线依赖安装与生产构建、`python3 scripts/check-repo.py` 和 `git diff --check` 均通过。 |

初次浏览器探针按「正在重连」精确匹配状态栏时超时。状态栏同时包含主机地址，改为核对状态栏内的状态文本后复验通过。撤权后的客户端清屏和重新加入时的工作区恢复由 [WEB-01-02](../topics/clients.md#web-01-02) 接续。
