# P1 实例切换与 SQLite 恢复验收

2026-11-15，[WEB-01-03](../topics/clients.md#web-01-03) 与 [OPS-01-04](../topics/deployment.md#ops-01-04) 通过本机验收。以 `085048a` 为源码基线叠加本轮实现，执行 `docker build --progress=plain -t radishchat:p1-web-switch-restore-20261115 .`。Linux ARM64 镜像 ID 为 `sha256:5562016e0a37e8a323fecda40e003a7427ad258d0457e4cbb156b94e3f69dd6c`。

环境为 macOS 27.0.1 arm64、OrbStack Docker 29.8.2、Compose 5.5.0 和 Caddy 2.11.4。主测试使用独立 SQLite 卷、合成账号与本机 HTTPS。使用测试 CA 分别验证了主机名及证书链。Playwright 驱动的 Chromium 按进程映射两个测试主机名并使用对应的公钥指纹。

| 场景 | 实际结果 |
| --- | --- |
| 实例切换 | 同一 Chromium 标签页经“切换服务器”和浏览器返回在 A、B 之间往返。两站使用相同用户名和数字会话 ID，账号显示、密码、会话列表和草稿仍各自独立。第一次进入 B 时无 A 的 Cookie，B 拒绝 A 的登录凭据。请求记录也确认登录及聊天请求走各自的同源 API。含路径的服务器地址被界面拒绝。 |
| 草稿和发送 | 在 A 落库后丢弃应用收到的发送确认。经 B 返回 A 时草稿仍在，重发使用原 `requestId`、返回 200，历史只有一条。B 的未发草稿仍可恢复。离开 A 时替换群成员资格，返回后旧草稿被清理。退出 B 会清除 B 的草稿，A 的会话仍可使用。 |
| 干净库备份与恢复 | 停止 A，从只读卷备份到权限为 `0700` 的目录，备份文件为 `0600`，库版本仍为 v3，`sessions` 和 `oidc_flows` 均为空。源实例重启后原会话可用。备份恢复到独立 Compose 项目的新卷，复跑恢复命令会拒绝已有目标。 |
| 恢复后登录 | 通过恢复环境的 HTTPS 入口携带恢复前有效的 Cookie，`/me`、会话列表、群成员、消息历史和 SSE 均返回 401。重新登录后，账号、会话列表、群成员和消息与备份前一致。恢复卷和数据库仍归 UID `10001`，模式为 `0700` 和 `0600`，另一非特权 UID 无法进入数据目录或读取数据库。 |
| 固定 v1 样本迁移回退 | 原样本的 SHA-256 保持为 `659c7c324189616b36af07b098337103b1a4ad21d3314824ef93bd75d2469129`。仅在副本注入阻止成员回填的触发器，候选容器退出并回滚，库仍为 v1，五条成员和五条消息均保留。另从升级前备份恢复 v1，确认[固定预览二进制](2026-11-14-p1-local-baseline.md)可登录并读取原群数据。独立恢复的干净副本用候选镜像升至 v3，完整性和外键检查通过。原私聊可读，旧群正文仍受历史下限限制，迁移后的新群消息可读。 |

`go test -mod=readonly -count=1 -race ./...`、`go vet -mod=readonly ./...`、镜像内 Web 生产构建、`python3 scripts/check-repo.py` 和 `git diff --check` 均通过。验收使用的浏览器状态、容器、网络及合成数据卷已清理，保留本地候选镜像。备份和迁移回退复跑入口见[部署说明](../../deploy/README.md#sqlite-backup-restore)。
