# P1 群成员加入边界与 SQLite v2 联合验收

2026-11-15，[MSG-01-02](../topics/messaging.md#msg-01-02) 和 [OPS-01-02](../topics/deployment.md#ops-01-02) 通过联合验收。以 `251f63c` 为源码基线，叠加本轮改动。在 macOS 27.0.1 arm64 上用 Go 1.26.3、Node.js 24.16.0 构建。HTTP 和 Chromium 实测访问本机服务与隔离 SQLite 副本。

| 检查 | 实际结果 |
| --- | --- |
| 加入、退出与重入 | 用首次加入前、首次在群、离群和重入后的消息验证授权。重入后旧游标无法取回旧消息，重试旧 `requestId` 返回 `409` 且只有错误说明。列表的 `lastMessageId` 只基于可见消息。离开或被移出后的成员、历史、增量和发送接口拒绝访问。 |
| 并发顺序 | 五组 HTTP 并发加人和写消息用例，在竞态检测下按实际记录的加入边界核对可见结果。成员看不到加人事务前写入的消息，可以读取之后写入的消息。 |
| 迁移与重启 | 固定 v1 样本副本升级到 `user_version=2`。逐项比对账号、房间、成员、消息、会话和 OIDC 表，原数据一致。对三位旧群成员写入同一个群消息下限 `5`，私聊下限为 `0`。`integrity_check` 为 `ok`，`foreign_key_check` 无异常。重启后，本地账号可登录，私聊仍能读到原消息，群历史、前翻和补拉均从迁移后首条新消息开始。写入新消息并再次重启，仍可读取这条消息。 |
| 失败和恢复 | 在固定样本的隔离副本上用临时触发器阻断成员回填。启动失败后 `user_version=1`、原成员表结构和原数据均保留。用升级前备份覆盖该副本后重新升级成功。Go 回归另验证空库初始化至 v2、未知版本拒绝启动和 v2 重开。 |
| 浏览器路径 | 在另一份样本副本上迁移后，用 Chromium 登录 Carol。群仍在列表中，打开时历史为空。Alice 经 API 发出迁移后的消息，已打开的群聊页面通过实时更新显示新消息。 |
| 工程检查 | `go test -mod=readonly -race -count=1 ./...`、`go vet -mod=readonly ./...`、Go 构建、Web 离线依赖安装与生产构建、`python3 scripts/check-repo.py` 及 `git diff --check` 均通过。 |

样本使用[固定预览 v1 生成与校验流程](../../testdata/preview-v1/README.md)。本次原样本字节 SHA-256 为 `659c7c324189616b36af07b098337103b1a4ad21d3314824ef93bd75d2469129`，逻辑 SHA-256 为 `735884915d1fce1f40f38f88874445114d7bf81e0c2d1bfaf9711ac06b89791f`。原样本在验收前后字节一致。
