# RadishChat 项目整体规划

更新日期 2026-11-15。阶段划分与首批范围是规划基线，首批合同已通过 BASE-02 评审。实施安排见[当前状态](../status/current.md)。

## 产品目标

让朋友和小群成员在自己选的服务器上随时聊天。本地账号独立可用，Radish 账号是可选入口。最早的完整场景是两位成员登录同一实例，互发 Markdown 私信，与同伴建立一个小群，遇到断网时恢复会话。部署人员能备份、恢复和升级，并把同一个服务器地址交给群成员使用。

RadishChat 专注独立的在线即时通讯。RadishNexus 承接团队协作，包括工单、决策和协作文档。Radish 承接社区内容与互动，保留社区内的聊天，可为 RadishChat 提供账号与后续入口。RadishLink 专注无网通信。每个 RadishChat 实例分别拥有账号、会话、成员关系、消息记录和设备授权。官方服务与自部署服务使用同一面向客户端的能力契约。

长期目标是让日常聊天好用，让第三方通过公开 Bot API 扩展聊天能力，让用户能理解并选择更强的私聊保护。支付、商城、小程序、内容广场、游戏和超级应用生态均在产品范围之外。语音视频、大型公开频道、联邦与跨实例迁移暂未排期。

## 产品参考

参考 Telegram 的日常私聊与群聊体验，以及 Discord 用讨论串组织群聊中并行话题的方式。将从群消息开讨论串与按串关注列为 [P2 群聊能力候选](../topics/messaging.md#msg-04-p2-candidates)。固定文字频道等内测反馈后再评估，重点看群里是否反复需要分开长期话题。P1 按[首个 Web 批次合同](first-web-slice.md)推进。[Telegram 群组 FAQ](https://telegram.org/faq#groups-and-channels) · [Discord 讨论串 FAQ](https://support.discord.com/hc/en-us/articles/4403205878423-Threads-FAQ)

## 技术与产品边界

- **栈与部署**。首批采用 Go 单进程、React 同源 Web、SQLite 和 REST/SSE。部署与恢复合同归 OPS-01，消息与同步合同归 MSG-02。Flutter 和移动端凭据按后续子专题评审。
- **身份**。本地注册与登录是独立可用路径。Radish 登录可选，使用标准 OIDC，以已验证的 `issuer + sub` 关联实例身份。账户合并、找回、注销、停用与设备恢复按各自合同设计。
- **聊天**。普通私聊和群聊先验证成员权限、消息去重、历史分页、断网补拉和 Markdown 安全渲染。普通消息的服务端可见范围在产品中明确说明。
- **开放与隐私**。Bot 的授权在其可访问的会话内单独授予。端到端加密先考虑一对一、多设备验证及历史恢复所需的成熟方案。消失消息先确定开始计时、离线补拉、设备和备份边界。相关产品声明以实际验收结果为依据。

## 里程碑与阶段出口

| 阶段 | 可交付目标 | 退出条件 |
| --- | --- | --- |
| P0 项目定义与治理 | 范围、专题、规则和首个实施批次可评审 | 总规划、专题与接续入口互相可查。首批场景、数据边界、方案和验收矩阵确认，已有预览明确如何采用或替换 |
| P1 Web 聊天与自部署内测 | 受控小团队通过 Web 和本地账号使用一个自部署实例 | 候选版本通过[内测放行条件](first-web-slice.md#p1-local-beta-gate)，覆盖注册准入、小群历史与撤权、断网补拉、隐私提示、备份恢复及固定合成预览 v1 库迁移。真实 Radish 登录延期并独立验收 |
| P2 群聊扩展与内测完善 | 使用一个可自建、可移除的 Bot，完善邀请、账户恢复和实例运维所需能力 | 第三方按文档安装和使用 Bot，只获得授权数据。密钥可轮换，撤销后同步停止。准入、举报、停用与数据处理在授权的内测环境得到验证 |
| P3 加密私聊与限时消息 | 提供有明确设备信任边界的一对一加密私聊，验证选定的消失语义 | 跨设备密钥、离线、换机、撤销、恢复、消失行为及服务端可见范围获得针对性验收。普通和加密会话有明确区分，Bot 不能读取加密私聊正文 |
| P4 Flutter 客户端 | 同一官方安装包可连接官方实例与用户指定的自部署实例 | 使用两个受支持的实例及目标真机验证服务器选择、账号隔离、重连、退出、协议兼容。推送和通知隐私按平台分别验收 |

P2 与 P3 可分别评审，实现顺序由 P1 的使用反馈、密码方案可行性和维护投入决定。P4 实施时点由 API 与设备身份边界的稳定性决定。各阶段的编号用于排序和追溯，具体任务与验收从[专题地图](../topics/README.md)进入。

## 首个实施批次

P1 首片覆盖用本地账号登录受控实例、创建私聊与小群、用 Markdown 收发消息、离线补拉，以及成员历史边界与撤权。账号、会话、收发和 Web 的功能合同分别归 [AUTH-01](../topics/identity.md#auth-01)、[MSG-01](../topics/messaging.md#msg-01)、[MSG-02](../topics/messaging.md#msg-02)、[MSG-03](../topics/messaging.md#msg-03) 和 [WEB-01](../topics/clients.md#web-01)。部署与恢复归 [OPS-01](../topics/deployment.md#ops-01)，普通会话采用 [P1 隐私边界](../topics/privacy.md#p1-privacy-boundary)，真实 Radish 接入的恢复条件见 [AUTH-02](../topics/identity.md#auth-02)。首批采用清单和联合验收见[首个 Web 批次合同](first-web-slice.md)。
