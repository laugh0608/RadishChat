# 会话、消息与同步

定义私聊、群组、成员权限、消息持久化与游标。Web、Bot 和 Flutter 都通过授权接口消费该能力。

阶段验收目标：两个账号能可靠收发，离线后得到按顺序且去重的历史。权限变更覆盖历史、发送和实时同步。

本页维护各子专题的设计与执行状态。跨专题顺序见[整体规划](../planning/project-plan.md)，近期优先级见[当前状态](../status/current.md)。

## MSG-01 私聊、群组与成员权限

- 阶段与状态：P1。私聊唯一性、成员操作及本次加入历史边界已通过单项验收。
- 范围：同一实例内两人共享唯一私聊。群主按完整用户名加人，也可从成员列表选择成员移除。普通成员可退出。群历史仅授权读取本次加入后产生的消息。重新加入时重新确定边界，前一次成员资格和离群期间的历史均不纳入本次授权。加入与消息写入之间的边界按服务端顺序确定。
- 预览采用：沿用私聊配对唯一性、群主权限、群成员关系和服务端访问检查。替换预览中新成员可见全量群历史的规则，将本次加入边界应用到历史与补拉。[探索验证](../status/2026-11-14-preview-verification.md)
- 验收：两人并行创建私聊得到同一会话。群主添加前、成员在群时、离开或被移出后及重新加入后的列表、成员、历史、发送和补拉均遵循当前授权。用加入前、两次成员资格之间及加入后各一组消息核对可见范围。其他实例账号和非成员的访问被拒绝，经 [WEB-01](clients.md#web-01) 验证撤权后页面清理。[P1 隐私边界](privacy.md#p1-privacy-boundary)

## MSG-02 收发、离线补拉与历史

- 阶段与状态：P1。消息确认、重试、分页与补拉均已通过单项验收。
- 范围：服务端以持久化的消息顺序提供历史分页和增量补拉。SSE 只发送通用同步信号，客户端通过 REST 读取当前房间授权和本次加入边界允许的消息。发送结果未知时，同一条待重试消息沿用原 `requestId`。
- 预览采用：沿用 REST/SSE、`requestId` 去重及双向分页。补齐多页补拉、历史分页与新消息交错时的恢复行为，并按 [MSG-01](#msg-01) 应用加入及撤权边界。部署依赖 [OPS-01](deployment.md#ops-01)，实时信号内容按 [P1 隐私边界](privacy.md#p1-privacy-boundary) 核对。
- 验收：模拟消息已保存但客户端未收到确认，原标识重试返回同一条记录，同标识不同正文返回冲突。断网累积超过一页，恢复期间持续发消息并翻历史，对比应见消息的顺序和数量。验证首次进入、离线恢复和重新加入均遵循本次成员资格，旧会话被拒绝，同步信号不含会话标识和正文。

## MSG-03 Markdown 与正文格式

- 阶段与状态：P1。正文与渲染已通过单项验收。
- 范围与预览采用：沿用 Markdown 原文与预览、收方共用的渲染路径。保留 GFM、列表、代码块及现有正文上限（8,000 个 Unicode 码点）。过滤原始 HTML，HTTP(S) 链接由用户主动打开，图片显示为占位文字。
- 验收：同一正文在编辑预览和收方呈现一致。覆盖列表、代码块、长度上限及超限拒绝、允许和不允许的链接、HTML 与图片占位。通过浏览器核对渲染期间无额外远程资源请求。[WEB-01](clients.md#web-01)
