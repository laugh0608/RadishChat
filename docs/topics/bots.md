# Bot 开放接口

让第三方在明确授权的会话中添加自动化。Bot 使用独立身份、权限和生命周期。

阶段验收目标：一个第三方按公开文档实现并安装 Bot，群成员可以查看它的访问范围，群主撤销后停止新访问。

本页维护各子专题的设计与执行状态。跨专题顺序见[整体规划](../planning/project-plan.md)，近期优先级见[当前状态](../status/current.md)。

<a id="bot-01-design"></a>

### 身份、安装与生命周期

Bot 开发者用实例内账号创建 Bot，获得由服务端分配的随机 Bot ID，并把 ID 交给需要安装它的群主。群主在群内核对 Bot 身份及它将获得的权限，再发起安装。若群主也是 Bot 所有者，操作可一次完成。两个角色由不同账号承担时，请求在 Bot 所有者同意后生效。安装成功后，群成员可在群内查看 Bot 名称和实际授权。开发者用独立凭据验证 Bot 接入，并检查指定群的当前安装状态。

| 主体 | 授权与可见范围 |
| --- | --- |
| Bot 所有者 | 管理本人创建的 Bot，签发、轮换或撤销该 Bot 的凭据，查看并处理该 Bot 的安装请求，可主动移除该 Bot 的任一安装。所有权本身不授予目标群成员、历史或正文访问。 |
| 群主 | 在自己当前管理的普通群内发起和移除安装。可确认实际权限，凭据由 Bot 所有者单独保管。 |
| 普通群成员 | 查看本群已生效的 Bot、展示名及权限。安装、审批、移除和授权变更都由服务端按对应管理角色校验。被撤销群成员资格后，群安装列表随群访问权限一并收回。 |
| Bot | 用独立凭据读取自身身份。`installation:read` 允许在生效的普通群安装中读取 Bot ID、群 ID、安装 ID 和实际权限。命令权限单独授予。私聊、加密会话、群成员、普通聊天正文和群历史都在 Bot 授权范围之外。[命令授权](#bot-02-delivery) |

Bot 所有者与群主的权限各自按当前账号校验。跨账号请求只向目标 Bot 所有者展示处理请求所需的群 ID、发起人和申请权限。待审批请求不给 Bot 访问权，也不出现在普通成员的群安装列表。群主撤回或 Bot 所有者拒绝时移除请求。审批使用服务端分配的安装 ID，并在提交前复查发起人仍为该群的当前群主。重复提交同一请求返回现有状态。同一群与 Bot 至多有一条待审批或已生效的安装，移除后再安装使用新 ID，旧审批不能激活新安装。新增数据权限在引入该能力的批次明确展示，并经群主重新授予。现有安装继续使用已有权限。

### 凭据、撤权与持久化

- 凭据由实例生成，使用至少 32 字节的密码学随机值，数据库仅保留摘要。每个 Bot 同时最多持有一个有效凭据，轮换在事务中替换摘要并于提交后返回新值。明文仅在签发或轮换成功后向所有者展示一次，响应沿用 `Cache-Control: no-store`，访问日志和诊断排除明文凭据。响应丢失后，所有者可再次轮换，通过最后一次成功签发取得新凭据。
- Bot 运行接口在 HTTPS 上通过 `Authorization: Bearer` 接收凭据。本机回环 HTTP 用于隔离测试。真人管理接口沿用 Cookie 和写请求的同源 `Origin` 校验。运行接口只接受 Bot 凭据，真人接口只接受真人会话。凭据放在请求头，拒绝从 URL、正文或 Cookie 读取 Bot 凭据。[RFC 6750](https://www.rfc-editor.org/rfc/rfc6750.html#section-2.1)
- 每次 Bot 群访问都在同一事务内核对当前凭据、普通群类型、生效安装与所需权限，从当前安装记录取得安装 ID。安装被移除后，该群的访问立即失效，其他群安装按各自授权继续使用。凭据撤销或轮换后，旧凭据在该实例的所有 Bot 路由失效。以撤销事务提交为界，提交后的请求使用新状态，提交前已获准的响应可能仍在传输。Bot 拉取事件和写入回复沿用这一判定，并校验请求属于当前安装。[BOT-02](#bot-02)
- SQLite v4 增加独立的 Bot 记录与当前凭据摘要，v5 增加群安装关系及明确授予的权限。迁移沿用外键、唯一约束和同一事务，保留既有消息、成员资格、历史下限和 Bot 凭据，失败时整次回滚。
- 备份和恢复保留 Bot 定义与所有者。v4 起清除副本中的 Bot 凭据，v5 起也清除待审批请求和生效安装。恢复后由所有者重新签发凭据，由群主按当前意愿重新安装，避免恢复先前已撤销的权限。正常重启沿用已保存的凭据和安装。数据库副本按其实际版本处理。[OPS-01](deployment.md#ops-01) · [备份与恢复说明](../../deploy/README.md#sqlite-backup-restore)

### API 与 Web 入口

以下路径相对于 `/api/v1`。真人管理使用当前实例会话，群安装列表复用现有群成员授权。[Bot 身份 API](../api/v1.md#bot-identity) · [群安装 API](../api/v1.md#bot-installations)

| 入口 | 操作与响应 |
| --- | --- |
| `GET /bots`、`POST /bots` | 所有者列出自己的 Bot 或用展示名创建 Bot。创建返回 Bot ID 和展示名。 |
| `POST /bots/{bot}/credential/rotate`、`DELETE /bots/{bot}/credential` | 所有者首次签发或轮换凭据，或撤销当前凭据。一次轮换只返回一份新明文，撤销可安全重复。 |
| `GET /rooms/{room}/bot-installations` | 当前群成员查看生效安装，返回安装 ID、Bot ID、展示名和实际权限。 |
| `GET /rooms/{room}/bots/{bot}/installation`、`PUT /rooms/{room}/bots/{bot}/installation` | 群主按 Bot ID 查看待安装的 Bot 名称、权限及当前安装状态，再显式提交 `permissions`。必须授予 `installation:read`，也可授予命令权限。详情见 [BOT-02](#bot-02-delivery)。修改现有安装的权限返回 `409`，须撤销旧安装后重新授予。 |
| `GET /bots/{bot}/installations`、`POST /bots/{bot}/installations/{installation}/approve` | Bot 所有者查看本人 Bot 的安装与待审批请求，或批准当前请求。 |
| `DELETE /bot-installations/{installation}` | 群主或该 Bot 的所有者撤回、拒绝或移除指定安装。使用安装 ID 定位，旧请求无法移除新的安装。 |
| `GET /bot/me`、`GET /bot/rooms/{room}/installation` | Bot 验证自己的身份或查询指定群的有效安装。安装查询仅返回 Bot ID、群 ID、安装 ID 和权限。可用 `X-RadishChat-Bot-Installation` 绑定期望的安装 ID。 |

Bot 凭据缺失、无效或失效时返回 `401`，附 Bearer 质询。有效凭据访问未安装或已移除的群统一返回 `404`。真人管理中，当前可见的群内操作权限不足返回 `403`，不可见资源统一返回 `404`。凭据轮换失败保留最后一次已提交状态。Web 在账号区提供所有者管理入口，在群内提供安装列表、权限和状态。只有具备对应角色的账号可看到管理操作，后端独立校验每次请求。

<a id="bot-01-web"></a>

### Web 操作

- Bot 所有者从账号区打开「管理 Bot」，创建或选择 Bot，可复制 Bot ID 给群主。在详情内签发或轮换凭据并保存到 Bot 运行环境。隐藏凭据、切换 Bot、退出管理、退出账号或切换实例都会清除当前页面的明文展示，重新打开管理只能看到 Bot 定义和安装状态。轮换或撤销会使旧凭据失效。
- 群主在群聊顶部打开「群 Bot」，输入 Bot ID，查看默认权限并按需勾选命令权限，再确认安装。跨账号安装由 Bot 所有者在「管理 Bot」的群安装列表中批准。群主可在群内撤回待审批请求或移除生效安装，Bot 所有者可在详情里拒绝请求或移除安装。普通成员可查看生效安装的实际权限，并向有接收命令权限的 Bot 发送 `ping`。
- 恢复数据库后，各角色重新登录。Bot 所有者选择保留原 ID 的 Bot 并签发新凭据，群主按需要重新发起安装，跨账号请求重新审批。[备份与恢复说明](../../deploy/README.md#sqlite-backup-restore)

<a id="bot-02-delivery"></a>

### 交付方式与授权

首批采用 Bot 主动发起的 REST 短轮询。事件保存在实例现有 SQLite 中，按安装读取，Go 服务可以在提交后立即返回。Webhook 需要实例主动访问外部地址，并另定回调地址校验、签名、投递重试及失败留存，等实际有回调需求时评估。长轮询需要管理连接寿命和反代超时，等短轮询的延迟和负载有实测数据后再评估。普通聊天继续使用现有 SSE 同步提示。

群主安装时可显式授予 `commands:receive`，需要 Bot 回复时再一并授予 `commands:reply`。现有安装保持原授权。新增权限经重新授予并生成新的安装 ID，跨账号仍由 Bot 所有者批准。`commands:reply` 限于当前安装收到的有效命令。普通群成员可在 Web 的「群 Bot」面板主动发出 `ping`，界面在入队后确认提交，Bot 的回复随后作为群消息出现。事件只包含成员提交的命令。普通聊天正文、群历史和成员名单在 Bot 授权范围之外。[命令事件 API](../api/v1.md#bot-command-events) · [回复 API](../api/v1.md#bot-command-replies)

### 事件、游标与重试

| 入口 | 接口与行为 |
| --- | --- |
| 真人调用命令 | `POST /api/v1/rooms/{room}/bot-installations/{installation}/commands` 使用 Cookie、同源 `Origin` 和当前成员资格。请求为 `{command, requestId}`，首批命令为 `ping`。同一事务核对普通群、当前成员、安装和权限，提交事件后返回 `202` 与事件 ID。同一安装、成员资格及 `requestId` 在去重窗口内重试返回原事件 ID，同标识改命令返回 `409`。 |
| Bot 读取事件 | `GET /api/v1/bot/rooms/{room}/events?after=…&limit=…` 使用 Bearer 凭据，并要求 `X-RadishChat-Bot-Installation` 为当前生效安装 ID。返回 `{events, nextCursor, hasMore}`，按提交序号升序。每项只包含 `{id, type, version, occurredAt, payload}`，首种事件为 `command.requested`、版本 `1`、`payload` 为 `{"command":"ping"}`。 |
| Bot 回复命令 | `POST /api/v1/bot/rooms/{room}/events/{event}/reply` 使用同样的 Bearer 和安装 ID，请求为 `{markdown}`。同一事务复核安装、回复权限及事件归属，使用绑定安装的事件 ID 保证每个事件只写一条回复。在事件有效期内，首次返回 `201`，相同正文重试返回 `200` 和原消息，正文变化返回 `409`，事件超期或被容量淘汰返回 `410`。真人写请求继续执行同源 `Origin` 校验。 |

- 事件序号在安装内单调递增，事件 ID 和游标为绑定该安装的不透明字符串，`occurredAt` 使用 Unix 毫秒。省略 `after` 表示从安装的开始位置读取。`after` 为排他边界，空页保持原位置，`hasMore=true` 时继续翻页。默认每页 25 条，上限 50 条。游标格式、安装归属或位置错误返回 `400`。
- 读取可以重复，每条事件可能交付多次。Bot 按实例和安装保存游标。回复收到 `201` 或同文重试收到 `200` 即确认。处理完整页后再持久化该页的 `nextCursor`。网络中断、超时及 `5xx` 使用带抖动的有上限退避，沿用上次保存的游标或同一事件回复。空页建议每隔 5 秒重试。每个 Bot 的每次安装每分钟可拉取 120 次，每个账号在同一安装每分钟可提交 60 条新命令。收到 `429` 遵循 `Retry-After`，已接受命令的幂等重试不占新命令配额。[HTTP 429](https://www.rfc-editor.org/rfc/rfc6585.html#section-4)
- 每次安装保留最近 1,000 条事件，拉取和回复时即检查 7 天有效期。后台每分钟清理过期事件，在同一事务更新清理边界。命令去重摘要独立保留 7 天，避免事件因数量限制提前清理后重复入队。回复遇 `410` 时，使用上次确认的游标重新拉取以取得缺口信息。拉取游标落在保留边界之前时返回 `410` 和 `resumeAfter`。示例 Bot 将记录缺口并提示操作者确认后从可用位置继续。命令请求在去重期结束后由成员重新发起。[HTTP 410](https://www.rfc-editor.org/rfc/rfc9110.html#section-15.5.11)

### 撤销、存储与回复兼容性

- 读页与写回复都在 SQLite 事务内重新核对凭据、群类型、安装 ID 和权限。移除与待交付事件清理在同一事务提交。提交后的新请求返回 `404`，已完成授权的响应可能仍在传输，先前交给 Bot 的副本由其运行者管理。凭据撤销或轮换后旧凭据返回 `401`。示例 Bot 收到 `401` 停止使用该凭据，收到 `404` 停止该安装的读取及回复，其他安装按各自授权继续使用。[SQLite 隔离与并发](https://www.sqlite.org/isolation.html)
- SQLite v6 增加接收权限、事件序号、事件及去重摘要。v7 增加回复权限，将群消息作者扩展为真人或 Bot，并保留旧消息的 ID、作者、内容、时间、发送标识和成员历史下限。迁移保留已有安装的实际权限。正常重启保留安装、游标边界和待交付事件。
- Web 在回复旁显示 Bot 展示名和 `Bot` 标识。消息 API 沿用真人作者 JSON，并为 Bot 作者提供 `kind: "bot"`、字符串 ID 和展示名。回复与真人消息共用顺序和历史边界。移除安装时清除该安装的授权与待交付事件，备份和恢复时清除副本中的授权、凭据与待交付事件，已发送回复按普通群历史保留。恢复后重新签发凭据并安装，使用新安装的独立游标。[备份与恢复说明](../../deploy/README.md#sqlite-backup-restore)
