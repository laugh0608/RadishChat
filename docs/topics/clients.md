# Web 与 Flutter 客户端

定义用户如何进入实例、看到自己的账号和会话，并在失败后恢复。Go 负责服务端授权，客户端负责交互和平台凭据。

阶段验收目标：小团队可经 Web 使用单实例。后续同一 Flutter 官方客户端可连接官方和自部署实例。

本页维护各子专题的设计与执行状态。跨专题顺序见[整体规划](../planning/project-plan.md)，近期优先级见[当前状态](../status/current.md)。

## WEB-01 Web 基础聊天工作区

- 阶段与状态：P1。本地准入、聊天主路径、发送恢复、撤权及独立主机名切换已通过单项验收。
- 范围与预览采用：沿用 React 同源工作区、按地址导航切换实例和窄屏主流程。整改发送失败、重连、撤权与重新加入后的页面状态，并提示普通会话的服务端可见范围。远程 Web 内测每个实例使用独立的 HTTPS 主机名，配合 Cookie 的主机作用域。[P1 隐私边界](privacy.md#p1-privacy-boundary)
- 验收：桌面和窄屏完成登录、私聊、小群、Markdown 预览、发送失败重试和离线恢复。用同一浏览器在两个独立主机名之间往返，核对凭据、会话和草稿隔离。被移出后清理已打开会话和相关页面状态，重新加入后按本次授权加载历史。用户可辨认普通会话的隐私类型。[AUTH-01](identity.md#auth-01) · [MSG-01](messaging.md#msg-01) · [MSG-02](messaging.md#msg-02) · [MSG-03](messaging.md#msg-03)

Web 用会话 ID 和当前成员资格标识确定会话页面。撤权后丢弃该页的历史、待发消息、草稿、预览和成员面板，并取消在途请求。会话列表直接更新为新成员资格时，即使页面未观察到离群状态，也会重新加载会话。发送响应丢失时保留草稿，重试沿用原标识。[API v1](../api/v1.md#group-history)

未发送或未确认的草稿保存在当前标签页该实例源的 `sessionStorage`，按账号、会话和成员资格定位。回到原实例并重新打开仍有访问权的会话时恢复原文和未确认的发送标识。发送确认后删除草稿，退出登录、会话失效或成员资格变化时清理对应存储。浏览器禁用存储时可继续在原页面编辑。

P2 的 Web 群 Bot 面板显示已授予的权限。普通成员可向获授权的安装发送 `ping`。收到入队确认前，面板内重试沿用同一请求标识。群内回复使用共用的 Markdown 渲染，并在发送者旁显示 `Bot` 标识。[Bot 管理与权限](bots.md#bot-01-web) · [桌面与窄屏验收记录](../records/2026-11-15-bot-command-replies.md)

登录页的「忘记密码？」接受维护者为当前实例的本地账号签发的一次性恢复码。密码重置成功后返回登录页，用户以新密码建立会话。关闭注册时，已有账号仍可进入恢复流程。[账号恢复设计](identity.md#auth-03-local-design)

普通群的可见消息提供「举报」入口，提交前说明当前实例维护者可查阅该条消息，提交后显示举报编号。审阅与结案由部署侧维护 CLI 执行。[举报与处置](deployment.md#ops-02-first-batch) · [P2 窄屏联合验收](../records/2026-11-17-p2-local-joint-acceptance.md)

## WEB-02 可访问性与隐私提示

- 阶段与状态：P2。规划，待开始。
- 范围：设计键盘操作、焦点和辅助阅读。定义连接状态、通知预览、隐私类型和权限变动的提示。
- 依赖与基础：依赖 WEB-01，协同 [LOCK-01](privacy.md#lock-01) 与 [BOT-01](bots.md#bot-01)。
- 验收：用键盘与小屏验证登录、导航、消息和错误恢复。用户能从会话据实辨认隐私与 Bot 权限。
