# 自部署与交付

运营者部署、升级、备份、恢复并诊断实例。正式支持矩阵覆盖前后端、数据库及 HTTPS 入口。

阶段验收目标：部署者可以重复完成安装、升级、备份恢复，并提供客户端可连接的地址。

本页维护各子专题的设计与执行状态。跨专题顺序见[整体规划](../planning/project-plan.md)，近期优先级见[当前状态](../status/current.md)。

### SQLite 升级与回退

停服后保留并验证独立的升级前数据库备份，再用新版本打开待升级数据库。当前版本为 `user_version=8`。启动时在同一事务内初始化空库，或将 v1 至 v7 逐步升至 v8。v3 为每条成员关系填入当前成员资格标识，沿用 v2 的历史可见下限。v4 加入 Bot 身份及凭据，v5 加入 Bot 群安装与授权，v6 加入命令事件及去重摘要，v7 加入回复授权和 Bot 作者字段。v8 加入账号状态、按用户撤销会话所用的索引和恢复码存储，已有账号迁为 `active` 并保留会话。升级保留已有安装的权限和消息 ID。迁移失败时回滚事务并拒绝启动，未知版本也会拒绝启动。需退回旧版本时，将升级前的备份恢复到新卷并用对应旧版本启动。用户须重新登录，Bot 所有者须重新签发凭据，群主须重新发起安装。[维护步骤](../../deploy/README.md#sqlite-backup-restore) · [账号状态](identity.md#auth-03-local-design)

v1 缺少加入记录。迁移时，包括群主在内的旧群成员都以迁移时该群的最大消息 ID 为历史下限。数据库保留原有账号、会话、成员和消息。旧群正文留在库内，群成员通过 API 从迁移后首条新消息开始读取。私聊仍可读取原历史。[群聊授权](messaging.md#msg-01)

## OPS-02 实例治理、诊断与隐私

- P2。首批范围、留存期和实施顺序已确认。[首批设计与验收](#ops-02-first-batch)
- 范围：负责运营者权限、准入执行、限制、举报、日志以及数据的留存、导出和删除流程。用账号停用和注销合同触发对应运营与数据处置，分别约定普通和加密会话涉及的明文。
- 依赖与基础：依赖 [AUTH-01](identity.md#auth-01)、[AUTH-03](identity.md#auth-03) 和 [MSG-01](messaging.md#msg-01)。先复用 AUTH-03 定义的账号状态及会话撤销行为，再确定运营权限、操作审计和数据处置。实际部署前评审对外运营口径。

### 受控内测首批设计

首批沿用实例现有的可信维护者。成员在 Web 举报自己当前可见的一条普通群消息。维护者在本机查阅举报，核实后结案或执行停用，并受理成员提出且经核实的本人资料请求。这个流程覆盖 P2 的准入、举报、停用与数据处理。当前已有邀请码注册和本机账号 CLI，应用诊断主要记录操作和错误类型，维护操作需要补可持久查询的审计。[P2 阶段出口](../planning/project-plan.md#里程碑与阶段出口) · [本地账号维护入口](../../deploy/README.md#local-account-disable)

#### 运营权限、准入和审计

- **维护者。** 复用部署环境的数据库维护权限，通过与实例版本一致的本机 CLI 查阅审计、处理举报和数据请求。首批应用权限维持现有的账号与群角色，运营操作由部署侧授权。CLI 审计记录来源为维护入口，个人归因由部署环境的身份与操作记录提供。数据库及备份访问者的明文可见范围沿用普通会话承诺。[普通会话隐私边界](privacy.md#p1-privacy-boundary)
- **准入与诊断。** 沿用默认关闭注册、受控开放和公网入口邀请码机制，复验邀请码轮换和关闭注册时已有账号可登录。维护者用现有健康检查、注册模式和结构化错误定位数据库、准入与反代问题。常规日志记录操作与结果类别，排除消息正文、请求正文、Cookie、邀请码、恢复码和 Bot 凭据。签发明文只向受保护终端交付。[准入配置](identity.md#local-admission-config) · [部署与反代](../../deploy/README.md)
- **持久审计。** 将停用、签发或重签恢复码、解除停用和后续的举报处置写入实例 SQLite，保存时间、维护入口、动作、目标 ID、结果和适用的举报 ID。成功审计与业务写入同一事务，审计失败则整体回滚。重复停用可复查已有结果。拒绝和数据库故障记录到脱敏诊断。审计查询只开放给维护者。[账号状态与撤权](identity.md#auth-03-local-design)

#### 举报与处置

- **提交。** Web 在普通群消息上提供举报，确认页说明将把选定消息交给本实例维护者。请求包含消息 ID 和枚举原因，返回举报编号。服务端在写入事务内复查有效会话、群成员资格、消息所属群与本次加入的历史下限。会话失效返回 `401`，不可见目标统一 `404`。同一成员重复提交同一消息及原因返回原编号，变更原因返回 `409`。按来源和账号限流。[群历史授权](../api/v1.md#group-history)
- **审阅。** 举报存储原消息引用、举报者账号、枚举原因、时间和处理状态。维护者通过本机 CLI 按举报编号查阅所指消息，原文交付前记录查阅审计。列表只展示必要元数据，原文沿用现有消息存储，引用失效时展示证据不可用。群主继续按群权限管理成员和 Bot 安装。[群权限](messaging.md#msg-01) · [Bot 授权](bots.md#bot-01)
- **结案。** 维护者明确选择结案结果。确需停用时，从所报消息核对本地账号作者，复用既有停用事务，并将举报结案及审计一并提交。Bot 举报转交群主评估移除安装。重复结案保持原结果，处置失败保留待处理状态。记录举报本身会保留供核实，账号撤权以停用事务提交为界。[停用行为](identity.md#auth-03-local-design)

#### 数据导出、留存和快照

- **导出。** 用户通过受控渠道提出请求，维护者核实本人身份后，仅导出该账号的基本资料、账号状态和本人提交的举报编号、原因、时间与状态。用字段白名单生成可核对的文件，保护文件权限和交付渠道。审计记录导出生成，维护者核对实际交付结果。群历史继续由聊天接口按现有成员授权读取。[群历史授权](../api/v1.md#group-history)
- **留存与清理。** 举报在结案后保存 30 天供复核，维护审计保存 90 天供处置追溯，待处理举报由维护者定期复核。通过本机维护命令清理到期记录并记录范围和数量，时间以结案或操作时间为准。验收应区分当前数据库的清理、旧快照和已交付的文件。账号注销、群主交接、共享消息删除与加密会话的数据边界分别评审。[账号生命周期](identity.md#auth-03) · [加密与留存](privacy.md)
- **快照恢复。** 私有备份按 OPS-01 管理。旧快照可能把已结案案件还原为待处理，恢复已清理的记录或较早的账号状态。重新开放实例前，对照快照之后单独保存的受保护维护记录，补做仍有效的停用、结案或清理并核对结果。用原时间判定到期，验证记录不会因恢复获得新的留存期限。[备份恢复说明](../../deploy/README.md#sqlite-backup-restore)
