# 自部署与交付

运营者部署、升级、备份、恢复并诊断实例。正式支持矩阵覆盖前后端、数据库及 HTTPS 入口。

阶段验收目标：部署者可以重复完成安装、升级、备份恢复，并提供客户端可连接的地址。

本页维护各子专题的设计与执行状态。跨专题顺序见[整体规划](../planning/project-plan.md)，近期优先级见[当前状态](../status/current.md)。

- 迁移基线：用固定预览版本生成 `user_version=1` 的合成数据样本，在隔离副本上验证迁移与失败回退。验收记录标明生成样本所用源码或产物版本、数据库版本与目标版本。涉及旧成员历史时，用合成样本验证正式的加入边界，缺少历史加入记录的场景以保守授权处理，不额外开放旧正文。[MSG-01](messaging.md#msg-01)
- 验收：完整构建候选产物，从干净目录安装并经目标 HTTPS 入口验证收发与断线恢复。分别验证合成预览库迁移、迁移失败后的备份恢复，以及干净安装产生的数据从备份恢复到新目录。核对账号、成员和消息，确认旧会话失效、重新登录后可用，并检查数据卷、备份和日志的访问边界。[P1 放行条件](../planning/first-web-slice.md#p1-local-beta-gate) · [P1 隐私边界](privacy.md#p1-privacy-boundary)

### SQLite 升级与回退

停服后保留并验证独立的升级前数据库备份，再用新版本打开待升级数据库。当前版本为 `user_version=4`。启动时在同一事务内初始化空库，或将 v1 至 v3 逐步升至 v4。v3 为每条成员关系填入当前成员资格标识，沿用 v2 的历史可见下限，v4 加入 Bot 身份及凭据。迁移失败时回滚事务并拒绝启动，未知版本也会拒绝启动。需退回旧版本时，保留失败库，将升级前的备份恢复到新卷，然后用对应旧版本启动。用户须重新登录，v4 恢复库里的 Bot 也须重新签发凭据。[维护步骤](../../deploy/README.md#sqlite-backup-restore) · [BOT-01](bots.md#bot-01)

v1 缺少加入记录。迁移时，包括群主在内的旧群成员都以迁移时该群的最大消息 ID 为历史下限。数据库保留原有账号、会话、成员和消息。旧群正文留在库内，群成员通过 API 从迁移后首条新消息开始读取。私聊仍可读取原历史。[群聊授权](messaging.md#msg-01)

## OPS-02 实例治理、诊断与隐私

- 阶段与状态：P2。规划，待开始。
- 范围：负责运营者权限、准入执行、限制、举报、日志以及数据的留存、导出和删除流程。用账号停用和注销合同触发对应运营与数据处置，分别约定普通和加密会话涉及的明文。
- 依赖与基础：依赖 [AUTH-01](identity.md#auth-01)、[AUTH-03](identity.md#auth-03) 和 [MSG-01](messaging.md#msg-01)。先复用 AUTH-03 定义的账号状态及会话撤销行为，再确定运营权限、操作审计和数据处置。实际部署前评审对外运营口径。
- 验收：用受控样本验证运营者可诊断故障、限制滥用和处理数据请求。与 AUTH-03 联合验证停用或注销后的会话拒绝、运营权限及留存、导出或删除结果。日志和监控仅保留声明所需字段。
