# 账号、身份与设备

实例负责账号、准入与会话。Radish 作为可选身份提供方，设备确认由独立合同定义。

阶段验收目标：P1 内测用本地身份完成准入与会话验收。后续验证 OIDC 与本地账号并存，账号关联有稳定主键。设备信任计划在加密前独立评审。

本页维护各子专题的设计与执行状态。跨专题顺序见[整体规划](../planning/project-plan.md)，近期优先级见[当前状态](../status/current.md)。

## AUTH-01 本地账号、会话与准入

- 阶段与状态：P1。默认准入、本地会话和公网邀请码已通过单项验收。
- 范围：本地注册默认关闭。部署者仅在受控入口按需开放，登记结束后关闭。内测入口直接暴露公网时，服务器须校验有效邀请码后才允许注册。账号恢复、停用和注销由 [AUTH-03](#auth-03) 定义。
- 预览采用：沿用实例内用户 ID、密码校验、服务端会话、HttpOnly Cookie 与写请求来源校验。整改默认注册策略和公网邀请码准入，并在 HTTPS 反代后验证限流与会话行为。[探索验证](../status/2026-11-14-preview-verification.md)
- 验收：干净安装后默认拒绝建号。受控入口按配置开放后，已知成员可注册。公网入口拒绝缺失或无效的邀请码，有效邀请码可完成注册。关闭注册后已有账号仍可登录。HTTPS 下核对 Cookie 的安全属性，确认退出或到期后的旧会话无法继续访问，单一来源触发限流时其他来源仍可登录。备份恢复后会话失效按 [OPS-01](deployment.md#ops-01) 联合验收。

### 本地准入与 HTTPS 反代

- Go 启动和 Compose 均默认关闭注册。`RADISHCHAT_REGISTRATION=on` 用于仅已知成员可访问的受控入口。公网内测入口开放注册时用 `RADISHCHAT_REGISTRATION=invite`。登记结束后设为 `off`，或移除该设置，再重启 Go 进程或更新 Compose 服务。已有本地账号可继续登录。已配置 Radish 登录的实例仅在 `on` 模式允许首次外部账号建号。
- 邀请码模式使用一枚可重复使用的实例级码。部署者用 `openssl rand -hex 24` 生成 48 位小写十六进制邀请码，通过部署环境设置 `RADISHCHAT_INVITE_CODE`，并私下交给已知成员。Go 和 Compose 都从该环境变量读取。邀请码缺失或格式无效时，邀请码模式拒绝启动。轮换时替换部署环境中的值并重启或更新服务，旧码随即失效。
- HTTPS 反代时，`RADISHCHAT_PUBLIC_URL` 填浏览器访问的 HTTPS 源地址。`RADISHCHAT_TRUSTED_PROXY_IP` 填 Go 进程实际看到的直连反代 IP。Go 进程与 Caddy 直接通过主机回环通信时可填 `127.0.0.1`，经 Compose 转发时以应用所见地址为准。后端端口只向反代所在的受控网络开放。
- 反代将 `X-Forwarded-For` 覆写为单个客户端 IP。Caddy 直接接收客户端连接时默认符合此约定。可信反代地址留空，或收到缺失、无效或多值的转发头时，按连接对端地址限流。登录还保留按账号单独限流。[Caddy 反代文档](https://caddyserver.com/docs/caddyfile/directives/reverse_proxy#defaults)

Web 注册表单根据 `/api/v1/info` 的 `registrationInviteRequired` 显示邀请码字段，并随注册正文提交 `inviteCode`。服务端在创建账号和会话前检查邀请码，缺失、错误或关闭注册均返回 `403`。邀请码保存在部署配置中，无 SQLite 结构变更。客户端字段及拒绝行为见 [API v1](../api/v1.md#registration-admission)。

## AUTH-02 Radish OIDC 登录

- 阶段与状态：后续，暂未排期。方案草案，执行延期，当前无稳定 Radish 实例可供真实联调和独立验收。[P1 内测](../planning/first-web-slice.md#p1-local-beta-gate)使用本地账号，关闭外部登录。
- 范围：按实例配置 OIDC，使用独立客户端，以经验证的发行方及主体标识建号和复用。首次登录与本地注册各自有明确准入。
- 依赖与基础：保留[合成发行方和回调证据](../status/2026-11-14-preview-verification.md)。Radish 侧有稳定实例后，由维护者确认测试发行方、独立客户端、受控测试身份和 HTTPS 回调，再安排真实联调。
- 预览采用：保留 OIDC 实现与合成发行方测试。P1 启动时省略 `RADISHCHAT_OIDC_*` 配置。缺省配置下，页面隐藏 Radish 登录入口，授权发起和回调返回 `404`，本地账号仍可登录和聊天。改动触及 OIDC 路径时复跑合成测试。
- 验收：复核重复登录、同名同邮箱不合并、取消及回调失败。真实联调独立记录实例、客户端配置范围、登录结果和失败路径。通过后再对外声明支持真实 Radish 登录。

## AUTH-03 账号恢复、停用与注销

- 阶段与状态：P2。规划，待开始。
- 范围：定义实例账号恢复、停用和注销的状态、授权入口及会话撤销合同。明确这些动作对实例身份、上游关联和授权的影响，并向运营流程提供可调用的结果。
- 依赖与基础：本地路径依赖 [AUTH-01](#auth-01)。涉及外部账号时引用 [AUTH-02](#auth-02) 的身份关联合同。本地路径可先验收。由 [OPS-02](deployment.md#ops-02) 消费账号合同并负责运营流程和数据处置。
- 验收：合法恢复后可重新访问站点，停用和注销后原会话按合同失效。将状态转换与撤权结果提供给 OPS-02 联合验收。隐私聊天密钥恢复由 [LOCK-01](privacy.md#lock-01) 验证。
