# 账号、身份与设备

实例负责账号、准入与会话。Radish 作为可选身份提供方，设备确认由独立合同定义。

阶段验收目标：P1 内测用本地身份完成准入与会话验收。后续验证 OIDC 与本地账号并存，账号关联有稳定主键。设备信任计划在加密前独立评审。

本页维护各子专题的设计与执行状态。跨专题顺序见[整体规划](../planning/project-plan.md)，近期优先级见[当前状态](../status/current.md)。

### 本地准入与 HTTPS 反代

- Go 启动和 Compose 均默认关闭注册。`RADISHCHAT_REGISTRATION=on` 用于仅已知成员可访问的受控入口。公网内测入口开放注册时用 `RADISHCHAT_REGISTRATION=invite`。登记结束后设为 `off`，或移除该设置，再重启 Go 进程或更新 Compose 服务。已有本地账号可继续登录。已配置 Radish 登录的实例仅在 `on` 模式允许首次外部账号建号。
- 邀请码模式使用一枚可重复使用的实例级码。部署者用 `openssl rand -hex 24` 生成 48 位小写十六进制邀请码，通过部署环境设置 `RADISHCHAT_INVITE_CODE`，并私下交给已知成员。Go 和 Compose 都从该环境变量读取。邀请码缺失或格式无效时，邀请码模式拒绝启动。轮换时替换部署环境中的值并重启或更新服务，旧码随即失效。
- HTTPS 反代时，`RADISHCHAT_PUBLIC_URL` 填浏览器访问的 HTTPS 源地址。`RADISHCHAT_TRUSTED_PROXY_IP` 填 Go 进程实际看到的直连反代 IP。Go 进程与 Caddy 直接通过主机回环通信时可填 `127.0.0.1`，经 Compose 转发时以应用所见地址为准。后端端口只向反代所在的受控网络开放。
- 反代将 `X-Forwarded-For` 覆写为单个客户端 IP。Caddy 直接接收客户端连接时默认符合此约定。可信反代地址留空，或收到缺失、无效或多值的转发头时，按连接对端地址限流。登录还保留按账号单独限流。[Caddy 反代文档](https://caddyserver.com/docs/caddyfile/directives/reverse_proxy#defaults)

Web 注册表单根据 `/api/v1/info` 的 `registrationInviteRequired` 显示邀请码字段，并随注册正文提交 `inviteCode`。服务端在创建账号和会话前检查邀请码，缺失、错误或关闭注册均返回 `403`。邀请码保存在部署配置中，无 SQLite 结构变更。客户端字段及拒绝行为见 [API v1](../api/v1.md#registration-admission)。

### 本地恢复与停用设计

首批面向能通过已有受控渠道确认成员身份的小群内测。忘记密码的成员联系实例维护者。维护者独立核实本人身份后，在有数据库维护权限的部署环境为指定本地账号签发短时一次性恢复码。成员在目标实例的 Web 登录页输入用户名、恢复码和新密码，成功后走常规登录。现有账号没有已验证的联系地址，本批以受控渠道完成身份确认。注销、数据留存和群主交接、外部身份恢复按各自专题评审。[实例治理](deployment.md#ops-02) · [Radish OIDC 登录](#auth-02)

| 当前状态 | 动作和授权 | 提交结果 |
| --- | --- | --- |
| 可用 `active` | 维护者 `radishchat account issue-recovery <user-id>` 签发 | 转为 `recovery_required`，撤销目标的真人会话，生成一枚恢复码。 |
| 待恢复 `recovery_required` | 维护者再次签发 | 维持待恢复，替换旧码。有遗失、过期或交付失败时可重签。 |
| 待恢复 `recovery_required` | 本人在 Web 提交有效恢复码与新密码 | 消费恢复码，替换密码并撤销全部旧会话，原账号恢复为 `active`。常规登录随后建立新会话。 |
| 可用或待恢复 | 维护者 `radishchat account disable <user-id>` 停用 | 转为 `disabled`，撤销会话和恢复码，并收回下面定义的 Bot 授权。对已停用账号重试幂等。 |
| 已停用 `disabled` | 维护者 `radishchat account reopen <user-id>` 同意解除停用并签发 | 转为 `recovery_required`，要求本人完成密码重置才恢复登录。停用期间签发和使用恢复码均被拒绝。 |

- **维护入口。** 命令是实例内的本机 CLI。操作者确认目标实例与实例内用户 ID，CLI 用 `RADISHCHAT_DATABASE` 打开版本匹配的现有库，复核目标为本地密码账号。未知目标、不适用的账号类型、状态不匹配或数据库繁忙均返回明确结果。状态与撤权在同一事务提交，提交后才交付码。32 字节随机值在实例内按账号绑定，仅保存摘要和到期时间，有效期 15 分钟。明文通过受保护终端一次交付，经受控渠道提供给本人。运维记录仅需实例、目标 ID、动作、时间和结果，运营角色与持久审计由 OPS-02 评审。[维护操作](../../deploy/README.md#local-account-disable)
- **恢复入口。** `POST /api/v1/auth/local/recover` 接受 JSON `{username,recoveryCode,newPassword}` 并校验同源 `Origin`。未知用户名、错误、过期、重复使用的码以及已停用状态统一返回 `401`。按来源和规范化用户名限流，复用密码规则和 Argon2 并发门限。用有效码提交的新密码若与当前密码相同，返回 `400` 并保留该码。密码散列在事务外计算，在写入事务中复查账号、恢复码摘要及有效期并一次性消费。成功返回 `204`。若成功响应丢失，先尝试用新密码登录。并行提交同一码时只允许一次成功。[恢复 API](../api/v1.md#local-account-recovery)
- **账号与会话。** 以数据库提交为授权界线。待恢复及停用账号的旧 Cookie 在会话入口返回 `401`。受保护的数据操作在同一事务或语句内复核有效会话与账号状态。登录在签发会话的事务内复查账号状态与已校验的密码散列，避免并发改密后用旧密码建立会话。SSE 在发出同步提示前以及现有 15 秒检查节拍复核会话，失效则关闭连接。Web 走现有 `401` 退出路径。撤权提交前已经获准的数据操作，其响应可能仍在排队或传输。OIDC 合成测试已覆盖正常账户登录与实例状态拦截，正式外部恢复流程待 AUTH-02。
- **群组与 Bot。** 账号 ID、用户名、成员关系、历史下限和消息归属继续保留。群主重新取得权限时，仍以当时的成员关系和所有权为准。`issue-recovery` 撤销真人登录，独立 Bot 授权继续有效。`disable` 同一事务撤销该账号所有 Bot 的凭据及其生效和待审批安装，并撤回该账号发起的其他待审批安装。已生效的其他所有者的 Bot 授权继续有效。Bot 定义和历史回复保留，重新接入须签发凭据和重新安装。[Bot 身份与撤权](bots.md#bot-01)
- **迁移与备份。** SQLite v8 给既有账号赋 `active`，增加恢复码存储并支持按账号撤销会话。迁移由服务启动路径在同一事务完成。沿用 OPS-01 的快照清理，v8 副本额外清除恢复码，保留快照中的账号状态和密码散列。旧快照可能恢复较早的密码或停用状态。恢复实例对成员重新开放前，维护者核对快照后的已知停用和密码重置，重新停用应维持停用的账号，为需要废止旧密码的账号发起恢复。待恢复账号由维护者核实后重签。[备份与恢复](../../deploy/README.md#sqlite-backup-restore)
