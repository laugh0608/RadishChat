# ADR 0001：社区和通讯产品独立，登录可接入 Radish

> 项目独立、可选接入 Radish 的方向沿用。本文中的 SQLite、REST/SSE 与 Web 凭据方式记录探索版本，正式技术决定按[整体规划](../planning/project-plan.md)和对应专题评审。

日期：2026-11-14。决定已用于开发预览。

Radish 保留社区内的频道与私聊。RadishChat 作为独立互联网 IM，拥有自己的 API、数据与发布节奏。RadishLink 保持无网通信方向。软件关注聊天本身，先服务小组的私聊和协作群。

- 身份：实例可以接受本地注册，也可将 Radish 作为 OIDC 发行方。实例只用已验证的发行方和 subject 关联内部分配的 ID；不依赖兄弟项目的数据库、角色和账号生命周期。
- 客户端：Go 服务同时提供 React 静态资源与 API，浏览器切换服务器会跳转到该站点，不跨站转发凭据。未来 Flutter 用实例根地址访问版本化 API，需另定系统浏览器登录回调、安全凭据存储和服务器隔离；当前 Cookie/Origin 契约暂不承诺为最终原生认证协议。
- 传输：恢复依赖持久化消息游标，SSE 只通知有更新，不携带消息正文或会话标识。当前使用单 Go 进程和一条 SQLite 连接；不规划拆分微服务来完成首版。
- 隐私：当前服务端可读正文。Markdown 保存原文，客户端不渲染 HTML、不自动加载外部图片，只允许显式打开 HTTP(S) 链接。支持同项目不同安全语义的会话时，应在界面和协议中显示安全类型，禁止静默降级；登录和恢复密码不构成设备信任。
- 开放：可自部署与可写 Bot 和跨实例互通是三个不同承诺。先把前两项做好；端到端加密优先评估现有协议与实现，当前没有自研密码协议。
