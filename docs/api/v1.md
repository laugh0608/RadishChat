# RadishChat Web API v1

> 本文记录 Web API v1 的探索基线及已实现的接口补充。消息与客户端合同分别见[消息与同步专题](../topics/messaging.md)和[客户端专题](../topics/clients.md)。

同源 JSON API，根路径 `/api/v1`。已验证环境不代表原生客户端的最终认证协议。生产运维由 HTTPS 反代终止 TLS。POST / DELETE 需要与实例公开 URL 完全一致的 `Origin`。带正文的请求使用 `application/json`；认证成功通过 HttpOnly Cookie 建立本站会话。REST 校验用户身份与房间成员身份，非成员查询房间统一返回 404。错误正文格式为 `{"error":"说明"}`。

| 方法和路由 | 请求与含义 |
| --- | --- |
| GET /info | 实例名称、API 版本、注册、Radish 登录和端到端加密开关 |
| POST /register | `username,password,displayName?`；注册并登录 |
| POST /login | `username,password`；本地登录 |
| POST /logout · GET /me | 退出；获取当前账号 |
| POST /auth/radish/start | 返回一次性授权流程的 `authorizationUrl` |
| GET /auth/radish/callback | OIDC 浏览器回调，成功跳到首页 |
| GET /rooms | 当前账号可见的会话 |
| POST /rooms/direct | `username`；返回会话 `id`，同一对账号会复用会话 |
| POST /rooms/group | `name,usernames`；最多 50 位成员（含创建者） |
| GET /rooms/{room}/members | 当前会话成员 |
| POST /rooms/{room}/members | `username`；群主添加成员 |
| DELETE /rooms/{room}/members/{member} | 群主移除成员，`member` 为实例内用户 ID |
| POST /rooms/{room}/leave | 非群主成员主动离开 |
| GET /rooms/{room}/messages | 缺省返回最近 50 条可见消息。`before` 读取指定 ID 之前的消息，`after` 读取指定 ID 之后的消息。`after=0` 从最早可见消息开始，适用于已确认历史为空后的补拉。边界 ID 不包含在结果中，结果始终按 ID 升序，`more` 表示该方向还有可见消息 |
| POST /rooms/{room}/messages | `markdown,requestId`。提交到数据库后首次返回 `201`。同一会话、用户、标识和原文在当前授权内重试返回 `200` 和原消息。相同标识遇到不同正文或已超出本次成员授权的原消息时返回 `409` |
| GET /events | SSE：连接、重连和有更新时发出 `sync` 提示；客户端使用 REST 游标补拉 |
| GET /healthz（无版本前缀） | 进程及数据库可访问性 |

用户、会话及消息 ID 均为实例内部整数。消息 `sentAt` 是 Unix 毫秒。消息支持 GFM、代码段和列表，原文最多 8000 个 Unicode 码点；服务端不承诺删除被接收者保留的副本。HTTPS 保护传输，当前正文仍由实例持久化。

<a id="group-history"></a>

## P1 群历史授权

群成员只能读取本次加入后产生的消息。会话列表的 `lastMessageId` 为最后一条可见消息的 ID，当前没有可见消息时为 `0`。`before`、`after` 和 `more` 均按当前可见范围计算。成员退出或被移除后，房间从其列表消失，访问成员和消息的有效请求返回 `404`。重新加入后，重试前一次成员资格使用过的 `requestId` 返回 `409`，响应只含错误说明。[会话专题](../topics/messaging.md#msg-01)

`GET /rooms` 的 `membershipId` 表示当前账号在该会话的本次成员资格。重新加入会生成新值，即使消息历史边界相同。客户端可在消息、成员和退出请求中传 `X-RadishChat-Membership`，服务端在读写事务中校验该值，旧值返回 `404`。省略请求头时，服务端按当前成员资格授权。SSE 继续发送通用同步提示。

<a id="registration-admission"></a>

## P1 本地注册准入

`GET /info` 保留布尔字段 `registration`，表示是否开放本地注册。`registrationInviteRequired` 为 `true` 时，客户端须在 `POST /register` 的 JSON 正文中带上字符串 `inviteCode`。邀请码缺失或错误时返回 `403`。关闭注册时，即使提供有效邀请码也返回 `403`。已有账号可通过 `POST /login` 登录。[部署配置](../topics/identity.md#local-admission-config)

<a id="bot-identity"></a>

## P2 Bot 独立身份与凭据

以下路由均以 `/api/v1` 为根路径。Bot 的 `id` 为实例生成的字符串。真人管理路由使用现有的会话 Cookie，写请求沿用同源 `Origin` 校验。`GET /bot/me` 使用 `Authorization: Bearer <token>`，远程连接使用 HTTPS。

| 方法和路由 | 请求与结果 |
| --- | --- |
| `GET /bots` | `200`，返回本人创建的 Bot 列表，每项为 `{id, displayName}`。 |
| `POST /bots` | JSON 正文 `{displayName}`。展示名去除前后空白后须为 1–48 个 Unicode 码点且无控制字符。创建成功返回 `201` 与 `{id, displayName}`。 |
| `POST /bots/{bot}/credential/rotate` | 所有者发起首次签发或轮换，提交后返回 `200` 与 `{token}`。上一份凭据同时失效。响应为 `Cache-Control: no-store`，明文仅在此响应中返回一次。 |
| `DELETE /bots/{bot}/credential` | 所有者撤销凭据，返回 `204`。再次撤销同一 Bot 也返回 `204`。 |
| `GET /bot/me` | 有效 Bot 凭据返回 `200` 与 `{id, displayName}`。凭据缺失或失效时返回 `401` 和 `WWW-Authenticate: Bearer realm="RadishChat Bot"`。该接口只接受一个 `Authorization` 请求头。 |

管理其他账号的 Bot 返回 `404`。签发响应丢失时再次轮换即可取回可用凭据，只有最后一次提交签发的凭据生效。正常重启保留凭据，备份或恢复的副本保留 Bot 定义及所有者，由所有者重新签发凭据。[BOT-01 合同](../topics/bots.md#bot-01) · [备份与恢复说明](../../deploy/README.md#sqlite-backup-restore)

<a id="bot-installations"></a>

## P2 Bot 群安装与撤权

真人路由使用会话 Cookie，写请求校验同源 `Origin`。`/rooms/{room}/...` 的 Bot 路由与聊天接口共用当前群成员授权，可用 `X-RadishChat-Membership` 绑定本次成员资格。本批只开放普通群的 `installation:read`。

| 方法和路由 | 请求与结果 |
| --- | --- |
| `GET /rooms/{room}/bot-installations` | 当前群成员取得生效安装列表，`200` 返回 `[{installationId, botId, displayName, permissions}]`。群主可传 `?includePending=1` 额外读取待审批安装，每项增加 `state`。普通成员请求 `includePending=1` 返回 `403`。 |
| `GET /rooms/{room}/bots/{bot}/installation` | 群主预览 Bot 和当前安装状态，`200` 返回 `{botId, displayName, permissions, state, installationId?}`。尚未安装时 `state` 为 `available`，省略 `installationId`。 |
| `PUT /rooms/{room}/bots/{bot}/installation` | 群主提交 `{"permissions":["installation:read"]}` 发起安装。其他权限组合返回 `400`。两个所有者相同时直接返回 `active`，跨账号返回 `pending`。`200` 响应同预览，重复提交已有安装返回同一安装 ID 和当前状态。 |
| `GET /bots/{bot}/installations` | Bot 所有者查看生效和待审批的安装，`200` 返回 `[{installationId, roomId, requestedBy, state, permissions}]`。`requestedBy` 是发起人的用户名。 |
| `POST /bots/{bot}/installations/{installation}/approve` | Bot 所有者批准待审批安装，服务端复核发起人仍为该群的当前群主和成员。成功和重复批准同一生效安装均返回 `204`。 |
| `DELETE /bot-installations/{installation}` | 群主或 Bot 所有者撤回、拒绝或移除指定安装，返回 `204`。已移除的安装 ID 返回 `404`，重新安装会生成新 ID。 |
| `GET /bot/rooms/{room}/installation` | 使用 Bot Bearer 凭据查询该 Bot 在指定群的生效安装。`200` 只返回 `{installationId, botId, roomId, permissions}`。可传 `X-RadishChat-Bot-Installation` 指定期望的安装 ID，旧 ID 返回 `404`。 |

Bot 凭据缺失或失效返回 `401` 并带 `WWW-Authenticate: Bearer realm="RadishChat Bot"`。有效凭据读取私聊、未知群、待审批或已撤销安装时返回 `404`。仅具成员权限的账号尝试管理本群可见安装或预览 Bot 时返回 `403`，尝试访问待审批请求时返回 `404`。移除只撤销该群的授权，轮换或撤销凭据作用于该 Bot 的各个群。恢复快照后须重新安装和签发凭据。[BOT-01 合同](../topics/bots.md#bot-01)
