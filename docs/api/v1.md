# RadishChat Web API v1

> 本文记录探索版本现有接口。正式 API 方案及采用范围见[消息与同步专题](../topics/messaging.md)和[客户端专题](../topics/clients.md)。

同源 JSON API，根路径 `/api/v1`。已验证环境不代表原生客户端的最终认证协议。生产运维由 HTTPS 反代终止 TLS。POST / DELETE 需要与实例公开 URL 完全一致的 `Origin`。带正文的请求使用 `application/json`；认证成功通过 HttpOnly Cookie 建立本站会话。REST 校验用户身份与房间成员身份，非成员查询房间统一返回 404。错误正文格式为 `{"error":"说明"}`。

| 方法和路由 | 请求与含义 |
| --- | --- |
| GET /info | 实例名称、API 版本、注册、Radish 登录和端到端加密开关 |
| POST /register | `username,password,displayName?`；注册并登录 |
| POST /login | `username,password`；本地登录 |
| POST /logout · GET /me | 退出；获取当前账号 |
| POST /auth/radish/start | 返回一次性授权流程的 `authorizationUrl` |
| GET /auth/radish/callback | OIDC 浏览器回调，成功跳到首页 |
| GET /rooms | 当前账号可见的会话 |
| POST /rooms/direct | `username`；返回会话 `id`，同一对账号会复用会话 |
| POST /rooms/group | `name,usernames`；最多 50 位成员（含创建者） |
| GET /rooms/{room}/members | 当前会话成员 |
| POST /rooms/{room}/members | `username`；群主添加成员 |
| DELETE /rooms/{room}/members/{member} | 群主移除成员，`member` 为实例内用户 ID |
| POST /rooms/{room}/leave | 非群主成员主动离开 |
| GET /rooms/{room}/messages | 最近 50 条，或用 `before` 向前、`after` 向后分页；结果始终按 ID 从小到大，`more` 表示该方向还有结果 |
| POST /rooms/{room}/messages | `markdown,requestId`；相同会话、用户和标识重试返回同一条消息；正文不同返回冲突 |
| GET /events | SSE：连接、重连和有更新时发出 `sync` 提示；客户端使用 REST 游标补拉 |
| GET /healthz（无版本前缀） | 进程及数据库可访问性 |

用户、会话及消息 ID 均为实例内部整数。消息 `sentAt` 是 Unix 毫秒。消息支持 GFM、代码段和列表，原文最多 8000 个 Unicode 码点；服务端不承诺删除被接收者保留的副本。HTTPS 保护传输，当前正文仍由实例持久化。

<a id="group-history"></a>

## P1 群历史授权

群成员只能读取本次加入后产生的消息。会话列表的 `lastMessageId` 为最后一条可见消息的 ID，当前没有可见消息时为 `0`。`before`、`after` 和 `more` 均按当前可见范围计算。成员退出或被移除后，房间从其列表消失，访问成员和消息的有效请求返回 `404`。重新加入后，重试前一次成员资格使用过的 `requestId` 返回 `409`，响应只含错误说明。[会话专题](../topics/messaging.md#msg-01)

<a id="registration-admission"></a>

## P1 本地注册准入

`GET /info` 保留布尔字段 `registration`，表示是否开放本地注册。`registrationInviteRequired` 为 `true` 时，客户端须在 `POST /register` 的 JSON 正文中带上字符串 `inviteCode`。邀请码缺失或错误时返回 `403`。关闭注册时，即使提供有效邀请码也返回 `403`。已有账号可通过 `POST /login` 登录。[部署配置](../topics/identity.md#local-admission-config)
